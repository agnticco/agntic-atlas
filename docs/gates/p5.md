## Evidence (beyond the grep-based gate script)

1. **Inventory (a)** — `GET /api/console/workflows` mounted, auth-gated via
   `requireActiveTenant`, passes `userId: req.user.id` + `tenantId: req.tenant.id`
   to `store.list()`. src/api/console.js:25-39. Mounted at src/api/server.js:795
   (`mountConsoleRoutes`). Runtime route registration confirmed: all 8 console
   routes register on a fake app with no import error.

2. **Run ledger** — `GET /api/console/workflows/:id/runs` passes both scopes to
   `store.getRuns()`, with post-query status/date/text filters.
   src/api/console.js:56-79.

3. **Per-step run render (b)** — `GET /api/console/workflows/:id/runs/:runId`
   passes both scopes to `store.getRun()` plus a `run.workflow_id` cross-check →
   404. src/api/console.js:83-99. Run rows persist a `steps` JSON array
   (workflow-store.js:581-583 write; :833 parse). The console drawer iterates
   `consoleDrawer.steps` rendering number/label/timing/output per step, with a
   "No step detail recorded for this run." fallback. public/index.html:995-1014.
   Client fetches the real endpoint at public/index.html:1980.

4. **Store tenant-scoping, fail-closed (e)** — `getRuns`
   (src/workflows/workflow-store.js:655-664) and `getRun` (:678-685) add
   `tenant_id IS ?` to the WHERE clause when `tenantId` is provided. The
   `workflow_runs` table carries a `tenant_id` column (schema :46-58, backfill
   :196-204), and `startRun` writes it from the parent workflow
   (:558-566: `INSERT INTO workflow_runs (... tenant_id ...)`), so legitimate
   tenant reads succeed while cross-tenant reads filter out.

   **Adversarial cross-tenant test (run live against the real WorkflowStore):**
   created tenant A's workflow + completed run, then queried as tenant B.
   Result: `getRuns` → 0 rows, `getRun` → null for tenant B; tenant A reads its
   own run (`tenant_id: tenantA`). PASS.

5. **SOP export, Markdown + PDF, derived from spec (c) + narrative UPS clause** —
   `GET /api/console/workflows/:id/sop` returns Markdown (or PDF when
   `?format=pdf`) generated by `generateSopMarkdown(wf)`. src/api/console.js:162-184.
   `generateSopMarkdown` (src/workflows/sop-generator.js:104-209) derives the
   document purely from the live spec (triggers, nodes, edges, per-step
   dependencies, data-flow chain). Run live against the frozen
   docs/specs/canonical-ups-slack.json: produced a 1290-char Markdown SOP
   documenting the email trigger (filter `from:ups.com`), the summarize step,
   the Slack #social delivery, dependencies, and the data-flow diagram; the PDF
   path emitted a valid 3722-byte `%PDF-` file. Client SOP export wired at
   public/index.html:2009 with format toggle.

6. **Console UI present, real data, no mocks (d)** — `modeConsole`,
   `consoleViewDash`, `consoleViewSop`, and `consoleDrawerOpen` present in
   public/index.html. The console fetches live console endpoints (inventory
   :1869; workflow+runs+metrics :1968-1970; per-run drawer :1980; pause :1992;
   run :2001; SOP :2009) — no mock run data (P4 Draft-page lesson respected).
