## Evidence (independently reviewed, not just script-trusted)

1. **Standalone admin app, separate from console** — `src/admin/server.js:23`
   `export function mountAdminRoutes(app, {...})`; mounted at
   `src/api/server.js:1624`. Admin UI shell served at `GET /admin`
   (`src/admin/server.js:33-37`), distinct from the user-facing console routes.
   UI is a 1136-line SPA at `src/admin/index.html`.

2. **Per-tenant run counts** — `GET /admin/tenants/:id/runs`
   (`src/admin/server.js:85-108`) returns `_tenantRunMetrics` (total/succeeded/
   failed/running/test, `src/admin/server.js:240-260`) plus a per-workflow
   breakdown, all scoped `WHERE r.tenant_id = ?` (`:99`). UI renders run totals
   and status bars (`src/admin/index.html:377,827,888`).

3. **LLM cost broken down by call type** — `GET /admin/tenants/:id/cost`
   (`src/admin/server.js:115-179`) groups `llm_cost_log` by `context`
   (`byContext`, `:122-134`). Contexts are real call-type tags: the UI classifies
   them into Conversation / Converger / Workflow execution / Web search
   (`src/admin/index.html:224-226`). Live DB confirms 10 distinct contexts across
   164 rows — e.g. `converger`, `web_search`, `workflow:generate_brand_kit_doc`,
   `chat.home` (`sqlite3 ... SELECT DISTINCT context FROM llm_cost_log`). The
   CostTracker persists every call: `src/api/server.js:591-620` wires
   `costTracker.setStore({ recordCost })` → `workflowStore.insertCostCall` →
   `INSERT ... INTO llm_cost_log` (`src/workflows/workflow-store.js:749`), with
   tenant attribution derived from `userId → tenant_id`.

4. **Estimated monthly burn per tenant** — `_tenantSpendProjection` /
   `_projectMonthly` (`src/admin/server.js:284-303`) compute `estMonthlyUsd` from
   trailing-30d spend projected to 30 days. Surfaced per tenant in the UI
   ("Est. monthly", `src/admin/index.html:649,811,852`) and platform-wide
   (`/admin/usage` `overallProjection`, `src/admin/server.js:206-211`).

5. **Error rates in real time** — run metrics carry `failed`/`total`; UI computes
   fail rate `t.runStatus.failed / (succeeded+failed)` (`src/admin/index.html:795`)
   and renders failed-run rows/status bars (`:372,525,888`). Data is live per
   request from `workflow_runs` (no snapshot/cache).

6. **Not visible to non-admin users** — every data route uses
   `adminOnly = [requireAuth, requirePlatformAdmin]` (`src/admin/server.js:29,52,
   68,85,115,184`). `requirePlatformAdmin` returns HTTP 403 unless the caller is
   an admin in the reserved platform tenant
   (`src/auth/middleware.js:111-116`: `req.tenant?.id !== PLATFORM_TENANT_ID ||
   req.user?.role !== 'admin'` → 403). The HTML shell is public but carries no
   data; `/admin/me` uses `optionalAuth` and returns `isAdmin` so the SPA gates
   itself.

7. **Cross-tenant isolation (not just filtering)** — every per-tenant helper and
   inline query is parameterised `WHERE tenant_id = ?` with the path's `:id`
   (`src/admin/server.js:99,131,143,157,169,249,269,300,313`); 9 tenant-scoped
   queries confirmed by the check. Live DB has 2 distinct tenants; a tenant id
   never widens to all rows.

8. **Syntax / wiring valid** — `node --check src/admin/server.js` and
   `node --check scripts/checks/p10-admin-metrics.mjs` both pass. `CostTracker` is
   instantiated (`src/api/server.js:591`), passed to `buildLLM(costTracker)`
   (`:629`) and `new WorkflowScheduler({..., costTracker })` (`:406`).
