## What P12 built (all merged to `main`, all in production)

Seven increments, A–G:

- **A** — the node library was re-cut, and a workflow's configuration is now
  checked against what each step actually reads. Keys nothing consumes are
  rejected instead of silently ignored.
- **B** — the engine gained control flow: conditional branches, loops, a durable
  pause, retries, and duplicate-write protection.
- **C** — the **outcome contract**: a workflow states what it will deliver, and a
  workflow that does not deliver on its own promise cannot be published.
- **D** — the **human approval gate**: a workflow can stop and ask a person, and
  the answer is authenticated before the engine accepts it.
- **E** — the **decision table**: routing rules a non-technical user can review,
  with a completeness proof behind them.
- **F** — connectors that read a destination's real schema, so a user is not asked
  to paste an Airtable base ID.
- **G** — the test panel as a live check of the promise, the procedure document
  carrying the contract, and a build path that requires no typing.

Shipped to production 2026-07-14 (v1.6.0, https://atlas.agntic.co), at the
operator's explicit direction, ahead of a passing checkpoint. It has been serving
real users since.

## Two rules from this phase that must never be weakened

Both look like technicalities. Both are load-bearing, and both are the kind of
thing a future session might "simplify" without understanding the cost:

- **A workflow may only branch on a value from a fixed, known list**
  (`LLM_INPUT_NOT_ENUM`). If the model can answer a routing question in free
  prose, nothing can prove the workflow handles every case — and the ability to
  prove that is the whole point of the promise system.
- **An approval must never be accepted from a reply email**
  (`EMAIL_REPLY_APPROVAL`). A "From" address is forgeable, and a forwarded thread
  is full of the word "yes". Approvals go through a signed, single-use link.
